## กอง A — แก้โค้ด

### A1 · SR-04 — แถบเตือนเมื่อไม่มีใครใกล้เคียงพอ

**อาการ** ค้น "กรรมการมวย" ได้ผู้สมัคร 20 คน คนแรกคะแนน 56 เป็นสาย
Investments / Events / Real Estate

**สาเหตุ ไม่ใช่บั๊ก** การค้นด้วยเวกเตอร์คืนเพื่อนบ้านที่ใกล้ที่สุดเสมอ
ระบบไม่มีแนวคิดเรื่อง "ใกล้ไม่พอ" จึงไม่มีอะไรจะบอกว่าไม่พบ

**ทางที่เลือก: เตือน ไม่ซ่อน** — แสดงผลครบเหมือนเดิม แต่ขึ้นแถบบอกเมื่อคะแนน
สูงสุดต่ำกว่าเกณฑ์ว่าไม่มีใครใกล้เคียงมากนัก

**เหตุผลที่ไม่ตัดผลลัพธ์ทิ้ง** เลขเส้นแบ่งต้องมาจากการวัด ไม่ใช่การเดา และการ
ซ่อนคนที่ควรเจอโดยไม่มีอะไรบอกคือความผิดพลาดชนิดเดียวกับที่โปรเจกต์นี้เจอมาแล้ว
หลายรอบ — ชิปตัวกรองที่ทำงานอยู่แต่มองไม่เห็น · `width: NaN%` · "ไม่พบผลลัพธ์"
ที่ขึ้นตอนระบบค้นหาพัง **ผลลัพธ์ที่หายไปเงียบๆ แย่กว่าผลลัพธ์ที่ไม่ดีแต่มองเห็น**

- เกณฑ์เป็นค่าคงที่ที่เดียว มีเทสต์ hardcode คู่ไว้
- ข้อความต้องไม่ใช้คำว่า "ไม่พบ" เพราะผลลัพธ์ยังอยู่ครบ

### A2 · DM-03 — ข้อมูลสังเคราะห์ไม่ต้องเตือนเรื่องนำเข้าซ้ำ

กล่องยืนยันการลบขึ้นคำเตือนว่าอาจถูกนำเข้ากลับมา ทั้งที่แถว `source = 'synthetic'`
ไม่มีทางถูกนำเข้าซ้ำ **คำเตือนที่ขึ้นทุกครั้งโดยไม่มีอะไรผิด สอนให้คนเลิกอ่านมัน**
แล้ววันที่มันเตือนเรื่องจริงจะไม่มีใครทันสังเกต — หลักการเดียวกับ `tolerateOutage`
และ cron ที่แดงทุกคืน

### A3 · AU-04 — ข้อความ error จาก Supabase ออกจอดิบ — **ทำแล้ว**

ตัวแปลงอยู่ที่ `lib/auth/authMessages.ts` ใช้ทั้ง `/login` และ `/signup`
**เทียบด้วยคำสำคัญ ไม่ใช่ข้อความเต็ม** เพราะ Supabase ไม่ได้รับประกันถ้อยคำ
และเปลี่ยนได้ทุกเวอร์ชัน — เทียบเต็มประโยคจะพังเงียบๆ ตอนอัปเกรด
ส่วนที่แปลไม่ได้ตกไปที่ข้อความกลาง ไม่ปล่อยของดิบออกไป

`login/page.tsx:20` และ `signup/page.tsx:23` ทำ `setMsg(error.message)` ตรงๆ
ผู้ใช้จึงเห็น "Invalid login credentials"

- ทำตัวแปลงข้อความที่เดียว ใช้ทั้งสองหน้า
- **ข้อความล็อกอินต้องไม่บอกว่าอีเมลมีอยู่จริง** → "อีเมลหรือรหัสผ่านไม่ถูกต้อง
  กรุณาลองใหม่" · **ห้ามใช้ "รหัสผ่านไม่ถูกต้อง"** เพราะจะทำให้ AU-04 ที่ผ่านแล้ว
  กลายเป็นไม่ผ่าน — หน้าสมัครยอมเผยเรื่องนี้โดยตั้งใจ แต่หน้าล็อกอินไม่ยอม
- ข้อความที่แปลงไม่ได้ให้ใช้ข้อความกลาง และ `console.error` ตัวเต็มไว้ฝั่งเซิร์ฟเวอร์
  (หลักเดียวกับข้อห้ามส่งข้อความ Postgres ดิบออกไป)

### A4 · AU-03 — หน้าลิงก์หมดอายุชี้ทางผิด — **ทำแล้ว**

ข้อความบอกให้ "ลองเข้าสู่ระบบ" ซึ่งใช้ไม่ได้กับบัญชีที่ยังไม่ยืนยัน แล้วบอกให้
สมัครใหม่ ซึ่งไปเจอ "อีเมลนี้ถูกใช้สมัครแล้ว" **ทั้งที่การสมัครซ้ำคือสิ่งที่ทำให้
Supabase ส่งอีเมลยืนยันฉบับใหม่จริงๆ** (`lib/auth/signupFlow.ts` บรรทัด 6-8)

**พิสูจน์แล้ว 18 ก.ย. — อีเมลฉบับที่สองมาจริง** (20:50 และ 21:03 กล่องจดหมายขึ้น
"Supabase Auth 2") การสมัครด้วยอีเมลเดิมที่ยังไม่ยืนยันทำให้ Supabase ส่งลิงก์ใหม่
ผู้ใช้จึงไม่ตัน **แต่ไม่มีข้อความไหนในระบบบอกเรื่องนี้เลย** ต้องบังเอิญไปเปิด
กล่องจดหมายเอง — เป็นการแก้ข้อความ ไม่ใช่การเพิ่มฟีเจอร์

**ระหว่างทดลองเจอตัวรบกวนที่เตือนไว้จริง** — รอบแรกชนโควตา SMTP แล้วหน้าสมัคร
ขึ้น `email rate limit exceeded` เป็นภาษาอังกฤษดิบ **ซึ่งทำให้ผู้ใช้สรุปว่าอีเมลนี้
ใช้สมัครไม่ได้ ทั้งที่ความจริงคือรอสักครู่แล้วได้** สองอย่างนี้ต้องทำคนละอย่างกัน
→ A3 ต้องมีกรณีนี้ด้วย: "ระบบส่งอีเมลถึงขีดจำกัดชั่วคราว กรุณารอสักครู่แล้วลองใหม่"

**ข้อความใหม่ของหน้าลิงก์หมดอายุ** ต้องครอบทั้งสองสภาวะ เพราะหน้านั้นไม่รู้ว่า
บัญชียืนยันแล้วหรือยัง:

> ลิงก์นี้หมดอายุหรือถูกใช้ไปแล้ว
> · ถ้ายืนยันอีเมลไปแล้ว — เข้าสู่ระบบได้เลย
> · ถ้ายังไม่เคยยืนยัน — สมัครด้วยอีเมลเดิมอีกครั้ง ระบบจะส่งลิงก์ใหม่ให้

**และต้องแก้ข้อความหน้าสมัครคู่กัน** — ตอนนี้เขียนว่า "อีเมลนี้ถูกใช้สมัครแล้ว
กรุณาเข้าสู่ระบบ หรือกดลืมรหัสผ่าน" ซึ่งสำหรับบัญชีที่ยังไม่ยืนยัน **ชี้ไปทางตันทั้งสองทาง
ทั้งที่ลิงก์ใหม่เพิ่งถูกส่งไปแล้วจริง** ต้องเพิ่มว่าถ้ายังไม่เคยยืนยัน ให้ไปดูกล่องจดหมาย

### A6 · บัญชีที่ไม่มีแถวใน `profiles` ได้สิทธิ์ member เงียบๆ — **ทำแล้ว**

**พบนอกตาราง UAT** ระหว่างทดลอง A4 เมื่อ 17 ก.ย. ผู้ทดสอบลบผู้ใช้แล้วสมัครใหม่
ด้วยอีเมลเดิมไม่ได้ · ตรวจกับฐานจริงพบว่า `siwakornt1999@gmail.com` **ยังอยู่ใน
`auth.users`** (`deleted_at` เป็น null) แต่ไม่มีแถวใน `public.profiles` แล้ว
สิ่งที่ถูกลบคือแถวใน `profiles` ไม่ใช่บัญชีใน Authentication → Users —
**FK cascade วิ่งทางเดียว** (ลบ auth user → ลบ profile ไม่ใช่ทางกลับ)

เดิม `getSession()` เขียนว่า `role: p?.role ?? 'member'` ผลคือบัญชีแบบนั้น:

- **ล็อกอินและใช้งานได้ตามปกติ** ทั้งที่ "ถูกลบไปแล้ว"
- **ไม่โผล่ใน `/admin/users`** ซึ่งอ่านจาก `profiles` — 6 แถวใน profiles แต่ 7 บัญชีใน auth
- แอดมินเปลี่ยนสิทธิ์ไม่ได้ ไม่มีแถวให้ update · `activity_log` ย้อนชื่อไม่ได้

**การลบแถวใน `profiles` จึงดูเหมือนถอดสิทธิ์ แต่จริงๆ แค่ทำให้คนนั้นล่องหน**
ซึ่งตรงข้ามกับสิ่งที่คนกดลบคาดหวังทุกประการ

**แก้แล้ว** — `lib/auth/profileGate.ts` (`decideAccess`) แยกสามสภาวะ:
อ่านล้มเหลว · ไม่มีแถว · `role` ที่ enum ไม่รู้จัก **ทั้งสามปิดประตู**
`getSession()` คืน `null` ซึ่งผู้เรียกทั้ง 40 ที่จัดการอยู่แล้ว ไม่ต้องแก้สักไฟล์

- **ลำดับการตรวจสำคัญ** ดู `hadError` ก่อน `!row` เพราะตอนอ่านล้ม row ก็เป็น null
  ตรวจสลับกันจะรายงาน "ไม่มีโปรไฟล์" ตอนฐานข้อมูลพัง แล้วไล่หาสาเหตุผิดที่
- **หน้า `/login` ต้องเช็คซ้ำเพื่อกันการวนลูป** ไม่ใช่เพื่อความปลอดภัย —
  ไม่มีด่านนี้ ผู้ใช้จะล็อกอินสำเร็จแล้วถูกเด้งกลับมาหน้าเดิมไปเรื่อยๆ
- ข้อความบัญชีไม่มีโปรไฟล์**ไม่บอกให้ลองใหม่** เพราะลองอีกกี่ครั้งก็เหมือนเดิม

**งานที่เหลือของข้อนี้ ผู้ใช้ต้องทำเองที่ Supabase:** ลบบัญชี `eda3cf9c-ad96-4fcd-88e2-88e604b06561`
(`siwakornt1999@gmail.com`) ที่ Authentication → Users เพื่อคืนอีเมลให้ใช้สมัครได้อีก
**และต่อไปให้ลบที่นั่นเสมอ ไม่ใช่ลบแถวใน `profiles`**

### A5 · AU-08 — สามหน้า auth ไม่มีทางกลับหน้าแรก — **ทำแล้ว**

## กอง B — แก้เอกสาร UAT ไม่แตะโค้ด

**ทุกข้อในกองนี้ระบบทำงานถูกอยู่แล้ว** เคสเขียนไว้ไม่ตรงกับสิ่งที่ระบบเป็น
