## ทำไมเคสชุดนี้ถึงแยกไฟล์ไว้

`skouth-uat.md` ออกแบบให้ผู้ใช้ทั่วไปทดสอบเองได้ด้วยเบราว์เซอร์อย่างเดียว
เคสในไฟล์นี้ทำแบบนั้นไม่ได้ เพราะต้อง**ยิงคำขอตรงไปที่ API โดยไม่ผ่านหน้าจอ**
หรือ**ทำให้บริการภายนอกล้มเหลวชั่วคราว** — จึงส่งให้ผู้ทดสอบภายนอกทำไม่ได้
แต่ก็**ตัดทิ้งไม่ได้** และเป็นเหตุผลที่ผู้พัฒนาต้องทำเอกสารฉบับรวม ไม่ใช่ทำแค่ไฟล์นี้

ส่วนใหญ่ของเคสที่นี่เป็นด่านความปลอดภัยที่หน้าจอปิดไว้แล้ว **แต่หน้าจอไม่ใช่ด่านจริง**
ถ้าทดสอบแค่ว่า "กดในหน้าเว็บไม่ได้" ก็เท่ากับไม่ได้ทดสอบด่านเลย

## คำสั่ง

**A — AD-02 (ลดสิทธิ์ตัวเอง)**

```js
await fetch('/api/admin/users', {
  method: 'POST',
  headers: { 'content-type': 'application/json' },
  body: JSON.stringify({ userId: '<ID ของตัวเอง>', role: 'member' }),
}).then(async r => ({ status: r.status, body: await r.json() }))
```

**B — ST-11 (ลบข้อมูลของคนอื่น)**

```js
await fetch('/api/self-assessment/<ID ของบัญชี A>', { method: 'DELETE' })
  .then(async r => ({ status: r.status, body: await r.json() }))
```

```js
await fetch('/api/self-assessment/<ID ของบัญชี A>/score', {
  method: 'POST',
  headers: { 'content-type': 'application/json' },
  body: JSON.stringify({ requirement: 'Data Scientist' }),

```

**D — SA-02 (อัปโหลดไฟล์ที่ไม่ใช่ PDF)**

สร้างไฟล์ข้อความปลอมๆ ขึ้นมาในหน่วยความจำ ไม่ต้องมีไฟล์จริงบนเครื่อง

```js
const fd = new FormData()
fd.append('file', new File(['ไม่ใช่ PDF'], 'notes.txt', { type: 'text/plain' }))
await fetch('/api/self-assessment/parse', { method: 'POST', body: fd })
  .then(async r => ({ status: r.status, body: await r.json() }))
```

## วิธีตรวจ ST-13

ข้อนี้**ตรวจด้วยการอ่านโครงระบบ ไม่ใช่ยิงคำขอ** เพราะสิ่งที่ต้องพิสูจน์คือ
"ไม่มีด่านอยู่" ซึ่งการยิงสำเร็จหนึ่งครั้งพิสูจน์ได้อ่อนกว่าการแสดงว่าทุกชั้นไม่มีด่าน

**ชั้นที่ 1 — ไม่มี route ของแอปที่เขียนคอลัมน์นี้**

```
npx tsx -e "0" ; findstr /s /i "display_name" app\api\*.ts
```

ผลที่ได้จริง: เจอเฉพาะ `app/api/admin/users/route.ts` ซึ่ง**อ่าน**ไปทำบันทึกกิจกรรม
ไม่มีที่ไหน `update` เลย · `components/DisplayNameCard.tsx` เขียนลง PostgREST ตรง

**ชั้นที่ 2 — คอลัมน์ไม่มีเพดานและไม่มี CHECK** (รันใน Supabase SQL editor)

```sql
select data_type, character_maximum_length from information_schema.columns
 where table_schema='public' and table_name='profiles' and column_name='display_name';
```

ผลที่ได้จริง 18 ก.ย.: `text` · `character_maximum_length` เป็น `null` · CHECK 0 ตัว

**ชั้นที่ 3 — สิทธิ์เขียนเปิดให้ผู้ใช้โดยตรง** อ่าน `migration 019` บรรทัด
`grant update (display_name, settings) on public.profiles to authenticated`

**สรุป: ด่านเดียวที่มีคือ `maxLength` ในฟอร์ม ซึ่งกันได้แค่การพิมพ์และการวาง**

### ถ้าอยากสาธิตให้เห็นกับตา (ไม่บังคับ)

`Copy as fetch` จาก Network แล้ววางใน Console — **ต้องลบ `"credentials": "include"`
ออกก่อน** ไม่งั้นโดน CORS บล็อก เพราะ Supabase ตอบ `Access-Control-Allow-Origin: *`
ซึ่งเบราว์เซอร์ห้ามใช้คู่กับ credentials mode `include` · และตอนแก้ค่า `display_name`
ให้ระวังไม่ไปทับ token ที่อยู่ใน header ซึ่งหน้าตาคล้ายกัน (`eyJhbGci...`)

**สองกับดักนี้เจอจริงทั้งคู่เมื่อ 18 ก.ย.** และ`import('@supabase/supabase-js')`
ใน Console ก็ใช้ไม่ได้ เพราะแก้ชื่อโมดูลเปล่าๆ ไม่ได้ในบริบทนั้น
— รวมสามทางที่ไม่เวิร์ค จึงเปลี่ยนมาตรวจด้วยการอ่านโครงระบบแทน

> ถ้าสาธิตแล้วบันทึกสำเร็จจริง **ตั้งชื่อกลับเป็นค่าเดิมทันที** ไม่งั้นแถวของคุณ
> ใน `/admin/users` กับบันทึกกิจกรรมจะเสียรูปไปตลอด

## วิธีทำให้ AI ล่มชั่วคราว (SR-05)

1. เปิดไฟล์ `.env` ที่รากโปรเจกต์
2. แก้ `GEMINI_API_KEY` เป็นค่าที่ใช้ไม่ได้ เช่น `GEMINI_API_KEY=broken`
3. **ปิดเซิร์ฟเวอร์แล้วเปิดใหม่** (`Ctrl+C` แล้ว `npm run dev`) — Next.js อ่าน `.env`
   ตอนเริ่มเท่านั้น ไม่แก้ตามระหว่างทาง
4. ค้นหาที่หน้า `/search` แล้วบันทึกผล
5. **คืนคีย์เดิมแล้วรีสตาร์ทอีกครั้ง** ก่อนทำอะไรต่อ

> **ห้าม commit `.env` ที่แก้แล้ว** — ไฟล์นี้อยู่ใน `.gitignore` อยู่แล้ว
> แต่ให้ยืนยันด้วย `git status` ว่ามันไม่โผล่ขึ้นมาก่อนไปต่อ
