# งานเตรียมก่อนส่งเอกสารให้ผู้ทดสอบ

> **ส่วนนี้มีเฉพาะในฉบับผู้พัฒนา** ผู้ทดสอบทั่วไปไม่เห็นและไม่ต้องทำ
> ทำให้เสร็จก่อน แล้วค่อยส่ง `skouth-uat.doc` ให้เขา

ฉบับผู้ใช้ถูกเขียนบนสมมติฐานว่า **ระบบพร้อมใช้และมีข้อมูลอยู่แล้ว** เขาแค่เปิด
เบราว์เซอร์แล้วทำตาม ทุกอย่างในหน้านี้คือสิ่งที่ทำให้สมมติฐานนั้นเป็นจริง
**ข้ามข้อใดข้อหนึ่งแล้วเคสจะไม่ผ่านเพราะการเตรียม ไม่ใช่เพราะระบบผิด** ซึ่งเป็น
ผลลัพธ์ที่แย่ที่สุดของการทดสอบ — ใช้เวลาไล่หาบั๊กที่ไม่มีอยู่

## 1. เซิร์ฟเวอร์และฐานข้อมูล

1. `npm install` แล้ว `npm run dev`
2. ตรวจว่า migration ใน `supabase/migrations/` ถูกรันครบใน Supabase SQL editor แล้ว
3. `npm test` ต้องเขียวทั้งหมดก่อนเริ่มทดสอบ — **เริ่ม UAT ทั้งที่ยูนิตเทสต์แดง
   คือการเอาคนไปเจอบั๊กที่เครื่องบอกไว้แล้ว**

## 2. ข้อมูลตัวอย่าง

```
npx tsx scripts/seed-synthetic.ts
npx tsx scripts/seed-jobs.ts
```

**ข้อมูลที่ได้เป็นคนสมมติทั้งหมด** จึงให้ผู้ทดสอบลบได้ตามที่เคสบอก

> **DB-03 ต้องเป็นเคสสุดท้ายที่ทำ** — มันสั่งลบผู้สมัครเป็นชุดราว 68 คน
> ทำก่อนแล้วเคสค้นหาและ Shortlist ที่เหลือจะไม่มีข้อมูลให้ทำงานด้วย

## 3. สามบัญชี

สมัครสามบัญชีผ่านหน้า `/signup` ตามปกติ แล้วยกระดับสองใบด้วย SQL

```sql
update profiles set role = 'admin'        where email = 'อีเมลใบที่หนึ่ง';
update profiles set role = 'data_manager' where email = 'อีเมลใบที่สอง';
```

**ต้องใช้ `where email = ...` ไม่ใช่ `display_name`** — จับผิดคอลัมน์จะได้
`UPDATE 0 rows` ซึ่ง**ไม่ใช่ error** แล้วจะงงว่าทำไมสิทธิ์ไม่ขึ้น (ดู migration 021)

ใบที่สามปล่อยเป็น `member` ตามค่าตั้งต้น

จากนั้น**กรอกอีเมลและรหัสผ่านทั้งสามใบลงตาราง "บัญชีสำหรับทดสอบ" ในฉบับผู้ใช้**
พร้อมที่อยู่ของระบบ — ตารางนั้นจงใจเว้นว่างไว้ให้กรอก

## 4. สองไฟล์ที่ต้องแนบไปกับเอกสาร

1. **CSV ตัวอย่าง** — ใช้ไฟล์ใน `docs/manual-tests/` ได้เลย (ชื่อสมมติทั้งหมด)
   ตรวจก่อนส่งด้วย `npx tsx scripts/check-linkedin-csv.ts <path.csv>`
   สคริปต์นี้ไม่แตะฐานข้อมูล ไม่เรียก Gemini ไม่ต่อเน็ต รันซ้ำได้ฟรี
   **ดูรายงาน "คอลัมน์ที่ไม่รู้จัก" เป็นหลัก** — คอลัมน์ที่ parser ไม่อ่านจะหายเงียบๆ
   ไม่มี error ไม่มีคำเตือน
2. **เรซูเม่ PDF** หนึ่งฉบับสำหรับเคสประเมินตัวเอง
   **ห้ามใช้ CV ของคนจริงที่ไม่ได้ยินยอม และห้ามวางไฟล์ไว้ใน repo**

## 5. ตรวจก่อนกดส่ง

- [ ] เปิดที่อยู่ของระบบจากเครื่องอื่นได้จริง ไม่ใช่แค่ `localhost` บนเครื่องตัวเอง
- [ ] ล็อกอินด้วยทั้งสามบัญชีได้ และเมนูที่เห็นต่างกันจริงตามระดับ
- [ ] อีเมลยืนยันการสมัครส่งถึงจริง (เคส AU-01, AU-03, AU-05 ขึ้นกับข้อนี้ทั้งหมด)
- [ ] ตาราง "บัญชีสำหรับทดสอบ" และ "ที่อยู่ของระบบ" ในฉบับผู้ใช้กรอกครบแล้ว
- [ ] แนบไฟล์ CSV และ PDF ไปด้วยแล้ว
- [ ] `git rev-parse --short HEAD` จดไว้แล้ว — **ผลทดสอบที่ไม่รู้ว่าทดสอบโค้ดชุดไหน
      ย้อนกลับไปหาสาเหตุไม่ได้**

## 6. ที่บันทึกผล

ผู้พัฒนากรอกผลที่ **`docs/uat/results.md`** บรรทัดละเคส:

```
AU-01 ผ่าน
AU-02 ไม่ผ่าน ปุ่มยืนยันไม่ขึ้น รอ 30 วินาทีแล้วยังไม่มา
```

ดูความคืบหน้าเมื่อไรก็ได้ด้วย `npx tsx scripts/uat-progress.ts`

> **ห้ามกรอกผลลงไฟล์ `.doc`** — `scripts/uat-to-doc.ts` สร้างไฟล์นั้นใหม่ทุกครั้งที่รัน
> ผลที่กรอกไว้จะหายหมดโดยไม่มีคำเตือน · ไฟล์ `.doc` เป็นแค่ฉบับอ่าน/พิมพ์
> ส่วนผู้ทดสอบภายนอกที่ได้ `skouth-uat.doc` ไปกรอกด้วยปากกาหรือใน Word
> ให้ผู้พัฒนาคัดลอกผลของเขามาลง `results.md` อีกทีเมื่อได้เอกสารคืน
