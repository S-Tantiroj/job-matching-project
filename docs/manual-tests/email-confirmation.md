# คู่มือทดสอบด้วยมือ — การยืนยันอีเมลตอนสมัคร

ส่วนที่เป็น logic ล้วนมี unit test คลุมแล้วที่ `lib/auth/signupFlow.test.ts`
(รันด้วย `npx vitest run lib/auth/signupFlow.test.ts`)

เอกสารนี้คือส่วนที่เขียนเป็น unit test ไม่ได้ เพราะต้องพึ่งการส่งอีเมลจริง
เซสชันจริงในเบราว์เซอร์ และการตั้งค่าใน Supabase dashboard

---

## ก. ลิงก์ยืนยันหมดอายุ / ถูกใช้ไปแล้ว

### A1 — ทดสอบหน้าจอ error โดยตรง (เร็วที่สุด ไม่ต้องรอ)

เปิด URL นี้ตรงๆ ขณะรัน `npm run dev`:

```
http://localhost:3000/auth/confirm?error=access_denied&error_code=otp_expired&error_description=Email+link+is+invalid+or+has+expired
```

**ผลที่ต้องได้:** หน้าขึ้นหัวข้อ "ลิงก์ยืนยันไม่ถูกต้อง" พร้อมคำอธิบายและลิงก์ไปหน้าเข้าสู่ระบบ
ต้องไม่ค้างอยู่ที่ "กำลังเข้าสู่ระบบ…" และต้องไม่เด้งไป `/dashboard`

ทดสอบซ้ำด้วยรูปแบบ fragment ซึ่ง Supabase ใช้ในบาง flow:

```
http://localhost:3000/auth/confirm#error=access_denied&error_description=Email+link+is+invalid
```

**ผลที่ต้องได้:** เหมือนกับข้างบน

### A2 — ลิงก์ที่ถูกใช้ไปแล้วจริงๆ (ทดสอบ end-to-end ได้เร็ว)

1. สมัครด้วยอีเมลใหม่ที่ยังไม่เคยใช้
2. เปิดอีเมล กดลิงก์ยืนยัน — ควรเข้า `/dashboard` ได้
3. ออกจากระบบ
4. **กดลิงก์เดิมในอีเมลซ้ำอีกครั้ง**

**ผลที่ต้องได้:** ขึ้นหน้า "ลิงก์ยืนยันไม่ถูกต้อง" เพราะ token ถูกใช้ไปแล้ว
นี่คือวิธีจำลองลิงก์หมดอายุที่เร็วที่สุดโดยไม่ต้องรอเวลาจริง

### A3 — ลิงก์หมดอายุตามเวลาจริง (ถ้าอยากยืนยันเป๊ะๆ)

1. Supabase dashboard → Authentication → Email → ตั้ง **Email OTP Expiration** ให้สั้น เช่น 60 วินาที
2. สมัครด้วยอีเมลใหม่ แล้ว **อย่าเพิ่งกดลิงก์**
3. รอให้เกินเวลาที่ตั้งไว้ แล้วค่อยกดลิงก์

**ผลที่ต้องได้:** หน้า "ลิงก์ยืนยันไม่ถูกต้อง"

**อย่าลืมตั้งค่ากลับ** เป็นค่าเดิม (ปกติ 24 ชั่วโมง) หลังทดสอบเสร็จ

### A4 — timeout กันผู้ใช้ค้างหน้าจอ

ปิดเน็ตแล้วเปิด `http://localhost:3000/auth/confirm` ตรงๆ (ไม่มี token ไม่มี error)

**ผลที่ต้องได้:** ขึ้น "กำลังเข้าสู่ระบบ…" ประมาณ 8 วินาที แล้วเด้งไป
`/login?confirmed=1` ซึ่งขึ้นข้อความเขียว "ยืนยันอีเมลเรียบร้อยแล้ว"
ต้องไม่ค้างที่หน้าโหลดตลอดไป

## ข. สมัครบน production (Vercel)

### ก่อนทดสอบ — ตั้งค่าให้ครบก่อน

ใน Supabase dashboard → Authentication → URL Configuration → **Redirect URLs**
ต้องมีทั้งหมดนี้:

```
http://localhost:3000/auth/confirm
http://localhost:3000/reset-password
https://<โดเมน-vercel>/auth/confirm
https://<โดเมน-vercel>/reset-password
```

และ **Site URL** ต้องชี้ไปที่โดเมน production

> ถ้าโดเมนของ production ไม่อยู่ในลิสต์ Supabase จะไม่ยอม redirect ไปที่นั่น
> แล้วจะโยนผู้ใช้ไป Site URL แทน — อาการคือกดลิงก์ยืนยันแล้วไปโผล่หน้าแรก
> ไม่ได้เข้า dashboard ซึ่งดูเหมือนโค้ดพักทั้งที่เป็นเรื่องการตั้งค่า

ตรวจว่า environment variables บน Vercel ครบ: `NEXT_PUBLIC_SUPABASE_URL`,
`NEXT_PUBLIC_SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_ROLE_KEY`, `GEMINI_API_KEY`

### B1 — สมัครใหม่บน production

1. เปิด `https://<โดเมน-vercel>/signup` ด้วยอีเมลที่ยังไม่เคยสมัคร
2. กดสมัคร

**ผลที่ต้องได้:** หน้า "ยืนยันอีเมลของคุณ" แสดงอีเมลที่กรอกไป

3. เปิดอีเมล **ตรวจว่าลิงก์ในอีเมลชี้ไปโดเมน production ไม่ใช่ localhost**
4. กดลิงก์

**ผลที่ต้องได้:** เห็นหน้า "กำลังเข้าสู่ระบบ…" แวบหนึ่ง แล้วเข้า `/dashboard` โดยไม่ต้องล็อกอินซ้ำ

### B2 — สมัครด้วยอีเมลซ้ำบน production

กรอกอีเมลจาก B1 ที่หน้า signup อีกครั้ง

**ผลที่ต้องได้:** ข้อความแดง "อีเมลนี้ถูกใช้สมัครแล้ว…" ไม่ใช่หน้ารอยืนยัน

### B3 — ตรวจ role และ profile ที่ถูกสร้าง

ล็อกอินด้วยบัญชี admin เปิด `/admin/users`

**ผลที่ต้องได้:** เห็นผู้ใช้ใหม่จาก B1 อยู่ในรายการ role เป็น `member`

### B4 — ลืมรหัสผ่านบน production

`https://<โดเมน-vercel>/forgot-password` → กรอกอีเมลจาก B1 → กดลิงก์ในอีเมล

**ผลที่ต้องได้:** เข้าหน้าตั้งรหัสใหม่ได้ และตั้งรหัสใหม่แล้วล็อกอินผ่าน

## ข้อควรระวังตอนทดสอบ

**โควตาอีเมล** — SMTP ในตัวของ Supabase free tier จำกัดการส่งไว้ต่ำมาก
(ระดับไม่กี่ฉบับต่อชั่วโมง) ถ้าทดสอบสมัครรัวๆ อีเมลจะหยุดมาเฉยๆ โดยไม่มี error
ในแอป **อย่าเพิ่งสรุปว่าโค้ดพัง** — เว้นระยะแล้วลองใหม่ หรือดู
Authentication → Logs ใน dashboard ว่าโดนจำกัดหรือเปล่า
ถ้าจะใช้งานจริงจังควรต่อ SMTP ของตัวเอง

**บัญชีที่สมัครแล้วไม่ยืนยัน** — trigger จาก migration 002 สร้างแถวใน `profiles`
ตั้งแต่ตอนกดสมัคร ไม่ใช่ตอนยืนยัน บัญชีทดสอบที่ทิ้งไว้จะค้างในหน้า `/admin/users`
ล้างได้ด้วย:

```sql
select u.email, u.email_confirmed_at
from auth.users u
where u.email_confirmed_at is null;
```

ลบผ่าน dashboard → Authentication → Users (การลบ auth user จะลบ profile ตาม
เพราะ `on delete cascade`)
