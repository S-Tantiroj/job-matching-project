# v5 — ย้ายแถบเมนูไปด้านซ้าย พับได้ พร้อมไอคอนและชื่อหน้าปัจจุบัน

**เป้าหมาย:** เปลี่ยนแถบเมนูของกลุ่ม `(app)` จากแถบบนที่เรียงลิงก์ข้อความ 11 รายการ
เป็น sidebar ด้านซ้ายที่พับได้ มีไอคอนกำกับทุกรายการ แยก "คู่มือ" กับ "ตั้งค่า"
ออกไปเป็นปุ่มไอคอนที่มุมขวาบน และเพิ่มชื่อหน้าที่เปิดอยู่บนแถบบน

**สถาปัตยกรรมโดยรวม:** `app/(app)/layout.tsx` ยังเป็น server component ที่เรียก
`getSession()` เหมือนเดิม แต่ส่ง `isAdmin` / `isDataManager` เป็น boolean เข้า
`components/nav/AppShell.tsx` ซึ่งเป็น client component ที่ถือสถานะพับ/กาง และรับ
`{children}` (ยังเป็น server component) ผ่านเข้ามา รายการเมนูทั้งหมดอยู่ใน
`components/nav/navItems.ts` ที่เดียว

**Stack:** เพิ่ม dependency ใหม่หนึ่งตัวคือ `lucide-react` ไม่มี migration ไม่มี
เส้นทางใหม่ ไม่แตะฐานข้อมูล ไม่แตะ API

## ขอบเขต

**อยู่ในรอบนี้:**

1. `components/nav/navItems.ts` — แหล่งเดียวของรายการเมนู ไอคอน และชื่อหน้า

5. `components/nav/navItems.test.ts` — เทสต์โครงสร้างรายการเมนูและความสอดคล้องกับ middleware

**ไม่อยู่ในขอบเขต:**

- แถบเมนูของกลุ่ม `(public)` (`/`, `/help`, `/terms`, `/privacy`) — ยังเป็นแถบบน
  `.pub-nav` เหมือนเดิม ไม่แตะเลย
- จำสถานะพับ/กางข้ามการเปิดหน้าใหม่ (เลือกแล้วว่าไม่เอา ดู "ทางเลือกที่ตัดออก")
- ไฮไลต์เมนูของหน้าที่เปิดอยู่ (เลือกแล้วว่าไม่เอา — ถามซ้ำสองครั้ง ยืนยันทั้งสองครั้ง)
- focus trap ใน drawer บนมือถือ (ตัดทอนโดยตั้งใจ ดู "สิ่งที่ยอมทิ้ง")
- เมนูซ้อนชั้น (submenu) และการจัดกลุ่มหัวข้อใน sidebar
- ย้าย `/help` เข้ามาอยู่ในกลุ่ม `(app)`

## ปัญหาของแถบเมนูเดิม

```tsx
<nav className="nav">
  <Link href="/dashboard" className="nav-brand">Skouth</Link>
  <Link href="/dashboard" className="nav-link">Dashboard</Link>
  ... อีก 8 ลิงก์ ...
  <div className="nav-right"><Link href="/settings">Setting</Link></div>
</nav>
```

สามข้อ:

1. **11 รายการเรียงในแนวนอน** ผู้ใช้ที่เป็น admin เห็นครบทุกอันจนเต็มความกว้าง
   การเพิ่มเมนูอีกหนึ่งรายการทำให้ตกบรรทัด
2. **ไม่มีอะไรบอกว่ากำลังอยู่หน้าไหน** — `.nav-link.active` มีอยู่ใน `globals.css`
   แต่ไม่เคยถูกใส่ให้ลิงก์ไหนเลย ต้องเดาจากเนื้อหาของหน้า
3. **รายการเมนูฝังอยู่ใน JSX ของ layout** จึงเอาไปใช้ที่อื่นไม่ได้ และเขียนเทสต์
   ครอบไม่ได้ — การกั้น role ของแต่ละลิงก์ไม่มีอะไรดักว่ามันยังถูกต้องอยู่

## รายการเมนู

`components/nav/navItems.ts` เป็นแหล่งเดียว ทั้ง sidebar, ปุ่มมุมขวาบน และชื่อหน้า
บนแถบบนอ่านจากที่นี่

```ts
export type NavItem = {
  href: string
  label: string
  Icon: LucideIcon
  placement: 'sidebar' | 'topRight'
  requires?: 'data_manager' | 'admin'
  /** เส้นทางที่เข้าได้โดยไม่ต้องล็อกอิน — ค่าปริยายคือ true */
  requiresAuth?: false
}
```

| href | label | Icon | placement | requires |
|---|---|---|---|---|
| `/dashboard` | Dashboard | `LayoutDashboard` | sidebar | — |
| `/search` | Search | `Search` | sidebar | — |
| `/jobs` | Job | `Briefcase` | sidebar | — |
| `/shortlists` | Shortlist | `Bookmark` | sidebar | — |
| `/self-assessment` | ประเมินตัวเอง | `ClipboardCheck` | sidebar | — |
| `/candidates` | ข้อมูล | `Database` | sidebar | `data_manager` |
| `/import` | Import | `Upload` | sidebar | `data_manager` |
| `/admin/users` | Admin | `Shield` | sidebar | `admin` |
| `/help` | คู่มือ | `HelpCircle` | topRight | — (`requiresAuth: false`) |
| `/settings` | ตั้งค่า | `Settings` | topRight | — |

**"คู่มือ" ย้ายออกจากรายการเมนูหลัก** ไปเป็นเครื่องหมาย `?` ที่มุมขวาบน และเปิดด้วย
`target="_blank"` เพราะ `/help` อยู่ในกลุ่ม `(public)` ซึ่งมี layout คนละตัว กดจากในแอป
แล้วจะหลุดออกจากโครง sidebar ทั้งหมด การเปิดแท็บใหม่ทำให้งานที่ค้างอยู่บนหน้าเดิม
ไม่หาย (พฤติกรรมเดิมคือเปลี่ยนหน้าไปเลย)

**การกั้นด้วย `requires` เป็นเรื่องความสะอาดของหน้าจอ ไม่ใช่ความปลอดภัย** —
`isAdmin` / `isDataManager` เดินทางไปถึง bundle ฝั่งเบราว์เซอร์ ใครแก้ค่าใน devtools
จะเห็นลิงก์ Admin โผล่ แต่กดเข้าไปไม่ได้เพราะ `middleware.ts` กันที่ฝั่งเซิร์ฟเวอร์
และ route handler ตรวจ role เอง ข้อนี้เป็นจริงกับของเดิมอยู่แล้วเพราะ layout เดิม
ก็ตัดสินใจจาก session แล้วส่ง HTML ที่ตัดลิงก์ออกไป — ผู้ใช้เห็นหรือไม่เห็นลิงก์
ไม่ใช่สิ่งที่กันการเข้าถึง

## โครงหน้าจอ

```
.shell            grid: [sidebar] [content]
├── .sidebar      sticky top:0, height:100vh, 208px (กาง) / 56px (หุบ)
│   ├── หัว       ปุ่มแบรนด์ "S" + คำว่า Skouth (ซ่อนเมื่อหุบ) + ปุ่มพับ/กาง
│   └── ลิงก์     ไอคอน + label (label ซ่อนเมื่อหุบ)
└── .content
    ├── .topbar   sticky: [แฮมเบอร์เกอร์ (จอแคบ)] [ชื่อหน้า] ... [?] [เฟือง]
    └── .container  คงเดิม max-width 960px
```

วงกลม "S" ตอนหุบใช้คลาส `.nav-avatar` ที่มีอยู่แล้วใน `globals.css` แต่ไม่เคยถูกใช้
แทนการเขียนคลาสใหม่

**ผลข้างเคียงที่ยอมรับ:** `.container` ยังกว้าง 960px เท่าเดิม แต่จุดกึ่งกลางของ
เนื้อหาขยับไปทางขวาตามความกว้าง sidebar ผู้ใช้ที่ชินกับตำแหน่งเดิมจะรู้สึกได้

### ชื่อหน้าบนแถบบน

หาโดยเทียบ `usePathname()` กับ `href` ของทุกรายการใน `navItems` แล้วเลือก
**อันที่ยาวที่สุดที่เป็นคำนำหน้าของ pathname**

- `/candidates` → "ข้อมูล"
- `/candidates/abc-123` → "ข้อมูล" (หน้ารายละเอียดใช้ชื่อของหมวด)
- `/settings` → "ตั้งค่า"
- ไม่ตรงอะไรเลย → "Skouth"

ต้องเลือกอันที่ยาวที่สุด ไม่ใช่อันแรกที่เจอ เพราะถ้าวันหนึ่งมี `/admin` กับ
`/admin/users` อยู่ด้วยกัน การหยุดที่อันแรกจะให้คำตอบตามลำดับในอาร์เรย์ ซึ่งเป็น
สิ่งที่คนแก้ไฟล์ทีหลังไม่มีทางรู้ว่ามีความหมาย

**ชื่อหน้าแสดงทั้งบนเดสก์ท็อปและมือถือ** ไม่ใช่เฉพาะมือถือ — ถ้าซ่อนบนเดสก์ท็อป
ครึ่งซ้ายของแถบบนจะว่างเปล่าโดยไม่มีเหตุผล

### จอแคบกว่า 780px

sidebar เลื่อนออกนอกจอ เนื้อหากินเต็มความกว้าง กดแฮมเบอร์เกอร์แล้วเลื่อนเข้ามา
**ทับเนื้อหา** พร้อมฉากหลังมืด ปิดได้สามทาง:

1. กดฉากหลัง
2. กด Esc
3. **เปลี่ยนหน้าเมื่อไรปิดเอง** — `useEffect` ที่ผูกกับ `pathname`

ข้อ 3 ไม่ใช่ของแถม layout ของ Next.js อยู่ข้ามการเปลี่ยนหน้าภายในกลุ่มเดียวกัน
สถานะของ client component จึงไม่ถูกล้าง ถ้าไม่เขียนไว้ พอกดลิงก์ในเมนูแล้วหน้าใหม่
โหลดเสร็จ drawer จะยังค้างทับอยู่และผู้ใช้ต้องกดปิดเองทุกครั้ง

จุดตัด 780px ใช้ค่าเดียวกับ breakpoint ที่มีอยู่แล้วสำหรับหน้า `/help`

## เทสต์

`components/nav/navItems.test.ts` — unit ล้วน ไม่แตะเครือข่าย

1. `href` ห้ามซ้ำ
2. ทุกรายการมี `label` ที่ไม่ว่าง มี `Icon` และมี `placement`
3. **รายการที่กั้นด้วย role ต้องเป็น `/candidates`, `/import`, `/admin/users` เป๊ะ** —
   ถ้าใครลบ `requires` ออกจาก Admin โดยไม่ตั้งใจ เทสต์แดงทันที
4. **ทุก `href` ที่ต้องล็อกอิน ต้องถูกครอบด้วย `matcher` ใน `middleware.ts`**
5. **`/help` ต้องไม่ถูกครอบด้วย matcher**

ข้อ 4 และ 5 อ่านซอร์สของ `middleware.ts` มาเทียบ วิธีเทียบ: ตัด `/:path*` ออกจาก
แต่ละรายการใน matcher เหลือคำนำหน้า (`'/admin/:path*'` → `'/admin'`) แล้วถือว่า
ครอบเมื่อ `href === prefix` หรือ `href.startsWith(prefix + '/')`

**ทำไมต้องมีข้อ 4:** เพิ่มเมนูชี้ไปหน้าใหม่แล้วลืมใส่ใน matcher = หน้านั้นเปิดได้
โดยไม่ต้องล็อกอิน และไม่มีอาการอะไรให้สังเกตเลยเพราะเมนูจะทำงานปกติ

**ทำไมต้องมีข้อ 5:** ทิศตรงข้าม — เผลอใส่ `/help` เข้า matcher แล้วคนที่ยังไม่
ล็อกอินจะอ่านคู่มือไม่ได้ ซึ่งเป็นข้อห้ามที่เขียนไว้ใน CLAUDE.md ("`matcher` เป็น
รายการเจาะจงที่ไม่ครอบสองเส้นทางนี้ **อย่าเพิ่มเข้าไป**") แต่ยังไม่มีอะไรดักไว้

เทสต์ทั้งสองข้อนี้จะแดงถ้ารูปแบบของ `matcher` เปลี่ยนไปจาก `'/xxx/:path*'`
ซึ่งยอมรับได้ — เป็นการบังคับให้คนที่เปลี่ยนรูปแบบมาอ่านเทสต์นี้

**ตรวจด้วยตา** (ผมรันเองไม่ได้จาก sandbox): `npm test`, `npm run build`,
`npm run dev` แล้วดูทั้งจอกว้างและจอแคบ

## ทางเลือกที่ตัดออก

**พับ/กางด้วย CSS ล้วน** (`<input type="checkbox">` + `.shell:has(:checked)`) —
ไม่ต้องมี client component เลย layout ยังเป็น server component 100% ทำได้เพราะ
เลือกว่าไม่จำสถานะ **แต่ตัดออกเพราะ** พอเพิ่มชื่อหน้าปัจจุบันบนแถบบน ก็ต้องใช้
`usePathname()` อยู่ดี ทางนี้จึงไม่ประหยัดอะไรอีกต่อไป และ `:has()` เป็นตัวเลือกที่
คนอ่านโค้ดทีหลังไม่คุ้น

**จำสถานะพับ/กางไว้ใน localStorage หรือ cookie** — ตัดออกตามที่เลือกไว้
localStorage อ่านได้เฉพาะฝั่ง client จึงมีจังหวะที่ sidebar กางแล้วกระพริบหุบหลัง
hydrate ส่วน cookie อ่านฝั่งเซิร์ฟเวอร์ได้ไม่มีกระพริบ แต่ต้องเขียน route หรือ
server action เพิ่มเพื่อบันทึกค่า ถ้าวันหนึ่งอยากได้ ให้เลือก cookie

**บนมือถือให้ sidebar เหลือแค่แถบไอคอน 56px** — เคยเป็นตัวเลือกแรกและถูกเปลี่ยน
เป็น overlay เพราะ **ไม่มีทางอ่านชื่อเมนูได้เลยบนจอสัมผัส** `title` ขึ้น tooltip
เฉพาะตอนเอาเมาส์ชี้ ผู้ใช้ต้องจำเอาว่าไอคอนไหนคืออะไร

**ไฮไลต์เมนูของหน้าที่เปิดอยู่** — ถามสองครั้ง (ครั้งที่สองตอนที่ `usePathname()`
เข้ามาแล้วด้วยเหตุผลอื่น ทำให้ต้นทุนเหลือไม่กี่บรรทัด) ยืนยันว่าไม่เอาทั้งสองครั้ง
ชื่อหน้าบนแถบบนทำหน้าที่บอกตำแหน่งแทน และ `.nav-link.active` ที่ค้างอยู่ใน CSS
โดยไม่เคยถูกใช้เลยจะถูกลบทิ้งพร้อม `.nav-link` (ดูตารางผลกระทบ) ไม่ใช่เก็บไว้รอ

## สิ่งที่ยอมทิ้ง

**ไม่มี focus trap ใน drawer** — เปิด drawer บนมือถือแล้วกด Tab ต่อไปเรื่อยๆ
โฟกัสจะหลุดไปโดนลิงก์และปุ่มที่อยู่ใต้ฉากหลังมืด ซึ่งคนใช้แป้นพิมพ์อย่างเดียวจะสับสน
ตัดออกเพราะเป็นระบบภายในที่ใช้บนเดสก์ท็อปเป็นหลัก และ drawer โผล่เฉพาะจอแคบ
ถ้าจะทำ ควรใช้ `<dialog>` ของเบราว์เซอร์ซึ่งได้ focus trap กับ Esc มาให้เอง แทน
การเขียน trap เอง

**ปุ่มพับ/กางหายไปบนจอแคบ** — บนจอแคบมีแค่ "เปิด/ปิด drawer" ไม่มีสถานะหุบแบบ
ไอคอนล้วน ปุ่มพับจึงไม่มีความหมายและถูกซ่อน

## ผลกระทบต่อของเดิม

| ของเดิม | เกิดอะไรขึ้น |
|---|---|
| `.nav` `.nav-brand` `.nav-link` `.nav-link.active` `.nav-right` | ลบออกจาก `globals.css` ทั้งหมด — ไม่มีที่ไหนใช้แล้ว (`.nav-link.active` ไม่เคยถูกใช้เลยตั้งแต่แรก) |
| `.nav-avatar` | **เก็บไว้และเริ่มใช้จริง** เป็นวงกลม "S" ตอนหุบ |
| `.pub-nav*` `.pub-wrap` | ไม่แตะ |
| `@media print` | ไม่แตะ — หน้าที่พิมพ์คือ `/help` ซึ่งอยู่กลุ่ม `(public)` |
| `.container` | ไม่แตะ ยังกว้าง 960px แต่ย้ายไปอยู่ในคอลัมน์ขวา |
