# ชุดเฉลย — วัดว่าการจัดอันดับดีขึ้นจริงไหม

การเปลี่ยนสูตร embedding ทำให้อันดับ **เปลี่ยน** เสมอ แต่ไม่ได้แปลว่า **ดีขึ้น**
การจะรู้ว่าดีขึ้นต้องมีเฉลยว่าใครเหมาะกับงานไหนจริง ซึ่งมีแต่คนเท่านั้นที่ตอบได้

## ทำไมไม่ให้ AI ติดป้ายเอง

ถ้าเฉลยมาจากตัวระบบเอง การวัดจะกลายเป็นการถามระบบว่า "เธอเห็นด้วยกับตัวเองไหม"
ซึ่งตอบว่าใช่เสมอ เฉลยต้องมาจากคุณ

## ทำไมชุดผู้สมัครถึงเป็นแบบรวม (pool)

`make-eval-set.ts` ไม่ได้เอาแค่ top-20 ของสูตรใดสูตรหนึ่ง เพราะถ้าทำแบบนั้น
สูตรนั้นจะแพ้ไม่ได้เลย — คนที่มันจัดอันดับต่ำผิดๆ จะไม่มีวันถูกติดป้าย
จึงไม่มีวันถูกนับเป็นความผิดของมัน

ชุดที่ได้จึงเป็น **การรวมกันของ top-15 จากทุกสูตร บวกคนสุ่มอีก 5 คน**
แล้วสับลำดับโดยไม่บอกว่าใครมาจากสูตรไหน คุณจึงตัดสินโดยไม่รู้ว่ากำลังเข้าข้างใคร

## ขั้นตอน

```
npx tsx scripts/make-eval-set.ts     # สร้าง eval/pool.js + rubric.json  (ใช้ embedding 8 ครั้ง)
```

เปิด `eval/label.html` ในเบราว์เซอร์ (ดับเบิลคลิกไฟล์ได้เลย ไม่ต้องมีเซิร์ฟเวอร์)

## ตรวจด้วยเกณฑ์ ไม่ใช่ความรู้สึก

เกณฑ์ถูกสร้างจากฟิลด์ของงานเอง (`title`, `required_skills`, `min_experience_years`,
`category`, `location`) เก็บไว้ที่ **`eval/rubric.json` ซึ่งคุณแก้ข้อความได้ตามใจ**
แก้แล้วรัน `npx tsx scripts/make-eval-set.ts --rubric-only` (ไม่แตะฐานข้อมูล ไม่ใช้โควตา)

ทำไมต้องมีเกณฑ์: การให้คะแนนด้วยความรู้สึกจะเลื่อนไปเรื่อยๆ ตลอดชั่วโมง
คนที่ 50 จะถูกตัดสินด้วยมาตรฐานที่ไม่เท่ากับคนที่ 1 เกณฑ์ที่เขียนไว้ก่อนตรึงมาตรฐานไว้
และทำให้ย้อนดูได้ว่าทำไมคนนี้ถึงได้คะแนนเท่านี้

**เกณฑ์ต้องถามถึงความสามารถจริง ไม่ใช่การมีอยู่ของคำ** ถ้าเขียนว่า
"มี Python ในรายการทักษะไหม" เฉลยจะกลายเป็นการเขียนสูตรจัดอันดับใหม่ด้วยคำพูด
แล้วทุกสูตรจะได้คะแนนดีด้วยเหตุผลที่ผิด — คนอ่านโปรไฟล์เต็มอนุมานได้ว่า
Data Scientist ที่ Agoda ย่อมเขียน Python เป็น ซึ่ง embedding ทำไม่ได้
ช่องว่างตรงนั้นคือสิ่งที่การวัดนี้ต้องการจับ

### วิธีติ๊ก

ติ๊กเฉพาะข้อที่ผู้สมัครทำได้จริง กด `1`–`9` สลับติ๊กแต่ละข้อ กด `space` เมื่อตัดสินเสร็จ
เพื่อไปคนถัดไป กด `←` เพื่อย้อน

ข้อที่มีแถบสีคือ **ข้อบังคับ** ไม่ผ่านแล้วคะแนนเป็น 0 ทันทีไม่ว่าข้ออื่นจะผ่านกี่ข้อ

### คะแนนมาจากไหน

หน้าเว็บ **ไม่แสดงคะแนน** และไม่ได้เก็บคะแนนด้วย — มันเก็บว่าคุณติ๊กข้อไหนบ้าง
การแปลงเป็น 0/1/2 เกิดที่ `scripts/eval-ranking.ts` ที่เดียว ตามกฎนี้

| เงื่อนไข | คะแนน |
|---|---|
| ตกข้อบังคับ | `0` |
| ผ่านข้อบังคับ แต่ข้ออื่นผ่านน้อยกว่า 60% | `1` |
| ผ่านข้อบังคับ และข้ออื่นผ่าน 60% ขึ้นไป | `2` |

ปรับได้ที่ `STRONG_RATIO` ใน `lib/eval/rubric.ts` จุดเดียว

## กฎข้อเดียวที่เกณฑ์ทุกข้อต้องผ่าน

**ต้องตอบได้จากโปรไฟล์ที่อยู่ตรงหน้า ไม่ใช่จากการเดาเจตนาหรืออนาคตของผู้สมัคร**

ข้อที่ตอบไม่ได้จะถูกเดา และการเดาคือ noise ที่กลบผลการวัด — ซึ่งเป็นสิ่งเดียวที่ชุดเฉลยนี้มีไว้เพื่อกำจัด
มีเทสต์ใน `lib/eval/rubric.test.ts` คอยกันคำอย่าง "ได้ไหม" "ยินดี" "ย้าย" ไม่ให้หลุดเข้ามาในเกณฑ์

**ข้อดีที่สำคัญที่สุดของการเก็บติ๊กแทนคะแนน:** อยากรู้ว่า "ถ้าไม่สนใจสถานที่ทำงาน
ผลจะต่างไหม" ก็ลบเกณฑ์ข้อนั้นออกจาก `rubric.json` แล้วรัน `eval-ranking.ts` ใหม่
ได้คำตอบทันทีโดยไม่ต้องกลับไปดูใครอีกเลย
ความคืบหน้าถูกบันทึกในเบราว์เซอร์อัตโนมัติ ปิดแล้วเปิดใหม่ได้

### ไม่ต้องติดป้ายทุกคน

รายการถูกเรียงมาแล้วตาม **ความขัดแย้งระหว่างสองสูตร** เพราะนั่นคือสิ่งที่ทำให้ป้ายมีค่า
ถ้าทั้งสองสูตรจัดใครไว้อันดับ 5 เท่ากัน ป้ายของคนนั้นไม่ได้บอกว่าสูตรไหนดีกว่า
แต่ถ้าสูตรหนึ่งจัดไว้อันดับ 3 และอีกสูตรจัดไว้อันดับ 18 ป้ายเดียวก็ชี้ขาดได้

จะมีเส้นคั่นบอกว่า **"พอแล้วสำหรับคำนวณผล"** ทุกอย่างเหนือเส้นนั้นคือรายการที่
ต้องมีเพื่อคำนวณ P@5 / P@10 ได้ ส่วนใต้เส้นแค่ทำให้ nDCG แม่นขึ้น ข้ามได้
แถบความคืบหน้าด้านบนนับเฉพาะรายการจำเป็น และจะขึ้นป้าย **"ครบแล้ว วัดผลได้"** เมื่อพอ

**หน้านี้ไม่แสดงว่าใครถูกจัดอันดับเท่าไร** โดยตั้งใจ ถ้าเห็นอันดับปัจจุบัน
การตัดสินจะเอนไปตามสิ่งที่ระบบคิดอยู่แล้ว แล้วเฉลยก็จะกลายเป็นเสียงสะท้อนของระบบเอง

เสร็จแล้วกด **ดาวน์โหลด labels.json** แล้ววางไฟล์ไว้ที่ `eval/labels.json`

```
npx tsx scripts/eval-ranking.ts      # เทียบสูตรเก่ากับสูตรใหม่
```

## อ่านผลอย่างไร

- **P@5 / P@10** — ในห้า (หรือสิบ) คนแรก มีกี่คนที่คุณให้ 1 ขึ้นไป
- **MRR** — คนที่คุณให้ 2 คนแรก อยู่อันดับที่เท่าไร ยิ่งใกล้ 1 ยิ่งดี
- **nDCG@10** — ตัวชี้วัดหลัก คิดทั้งว่าใครติดและอยู่อันดับไหน 1.0 คือเรียงได้ดีที่สุดเท่าที่เป็นไปได้

**ส่วนต่างต่ำกว่า 0.05 ให้ถือว่าเสมอ** ด้วยจำนวนงานระดับนี้ ความต่างเล็กน้อยคือ noise
ถ้าสูตรใหม่แย่กว่าชัดเจน ให้ย้อน `buildJobEmbedText` กลับเป็นเวอร์ชันใน
`lib/jobs/legacyEmbedText.ts`

## ข้อควรระวัง

- `pool.js` และ `labels.json` มีข้อมูลส่วนบุคคลจริง **ถูก gitignore ไว้แล้ว อย่านำขึ้น GitHub**
- ยิ่งงานมาก ผลยิ่งเชื่อถือได้ ตอนนี้มี 4 งานซึ่งบอกได้แค่ทิศทาง ไม่ใช่ข้อสรุป
- ติดป้ายให้ครบทุกคนในชุด อย่าเลือกติดเฉพาะคนที่ดูดี — คนที่ถูกจัดอันดับสูงผิดๆ
  คือหลักฐานสำคัญที่สุด และมันจะหายไปถ้าคุณข้ามเขา
